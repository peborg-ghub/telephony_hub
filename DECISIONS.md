# Decisions

Choices made where the spec was open or where Astro required a specific approach.

| # | Decision | Why |
|---|---|---|
| 1 | **Astro 7.4.1, Node 24 LTS**, pinned in `.nvmrc`, `package.json` `engines` and `netlify.toml`. | Latest stable versions as of 2026-10-20. |
| 2 | Added the dev dependencies **`@astrojs/check`** and **`@types/node`**. | `astro check` requires `@astrojs/check`. TypeScript 6 needs Node's type definitions to understand `node:fs`. Both are dev-only and never ship to the site. |
| 3 | Pre-build scripts are `.ts` files run directly by Node (`node scripts/check-files.ts`). | Node 24 runs TypeScript natively, so no `tsx`/`ts-node` dependency is needed and it works the same on Windows and Netlify. |
| 4 | `documents.yaml` is loaded with Astro's **`file()` loader** and a custom parser that gives each entry an id like `#3 Q3 Call Volume Summary`. | `file()` requires an `id` on every entry, and building it from the position and title makes build errors point at the right entry. |
| 5 | Checks on single entries live in the **Zod schema** (`src/lib/documents-schema.ts`). Checks on the whole file (invalid YAML, duplicate `file`/`url`) live in `src/lib/documents-file.ts` and run from `getDocuments()`. | Astro only *logs* errors thrown inside a loader and keeps building. Throwing during page rendering reliably fails the build. Verified: a duplicate file passed the build before this change and fails it after. |
| 6 | The schema is **strict**: unknown fields (e.g. `tag:` instead of `tags:`) fail the build. | A typo would otherwise be dropped silently. |
| 7 | File paths are checked with **exact capitalisation**. | Windows ignores case but Netlify (Linux) doesn't, so `Report.PDF` vs `report.pdf` would work locally and 404 once deployed. |
| 8 | Files must sit in the folder that matches their `section`/`subsection`. | This keeps `public/files/` organised and catches a document filed under the wrong section. |
| 9 | `owner` defaults to "Pete" and `tags` to `[]`. | Fewer fields to type per entry. |
| 10 | Dates show as "Oct 20, 2026". The footer's build date is calculated in `America/New_York` (`src/lib/site.ts`). | Netlify builds in UTC, so an evening build would otherwise show tomorrow's date. Change `SITE_TIMEZONE` if the team is elsewhere. |
| 11 | The header is sticky on tablet and desktop only. | On a 360px phone the nav wraps to a second row, and a sticky header would cover about a fifth of the screen. |
| 12 | Tags on cards are `<button>`s that filter the library (wired up in Phase 3). Without JS they do nothing, and all cards still show. | The spec asks for clickable tag chips that drive the filter. |
| 13 | PDF "Open" uses `target="_blank"`. Other file types use the `download` attribute. | Matches the spec. Browsers handle `download` for same-site files. |
| 14 | Library filter controls start `hidden` and the script reveals them. | Without JavaScript you see every card and no controls that don't work. |
| 15 | Search matches every word typed, in any order ("call volume" finds "Call Volume Tracker"), and is case-insensitive. | It's more forgiving than matching the exact phrase. |
| 16 | `practices.csv` is validated in `src/lib/practices.ts` with `csv-parse` and embedded in the page as JSON. Only the fields the lookup shows are included. | Static site, no server. A bad CSV fails the build with line numbers, and every problem is listed at once so you can fix them in one pass. |
| 17 | Header row must match exactly, and every row must have 16 columns. | Catches renamed or reordered columns, and unquoted commas inside a value. |
| 18 | "Today" in the hours table uses the **practice's** time zone, not the viewer's. A friendly time zone name is shown (e.g. "Central Time (America/Chicago)"). | Matches the spec. Verified with a faked clock: at 00:30 Wednesday Eastern, a New York practice shows Wednesday and a Chicago practice shows Tuesday. |
| 19 | The lookup announces "Found <practice> for <number>." in a live region and builds the card outside it. | Screen-reader users hear a short summary instead of the whole card being read out. |
| 20 | Practice data is public. Anyone with the URL can view the full list in the page source. | This is what the spec describes (no password). If it needs to be private, turn on Netlify password protection or put the site behind company sign-in (SSO). |
| 21 | Added `scripts/check-colors.ts` to `npm run check`. It checks WCAG AA contrast for 18 text/background pairs in both themes, confirms the two dark-theme blocks match, and finds hardcoded colors outside `tokens.css`. It is **not** run by `npm run build`. | You'll be changing the brand colors later, and this catches unreadable combinations immediately. It's left out of the build so a color tweak can never block an urgent content deploy. Current lowest ratios: light 5.63:1, dark 6.54:1. |
| 22 | On screens under 480px the lookup card uses tighter padding, and hours never wrap. | At 360px, "9:00 AM – 5:00 PM" was wrapping onto two lines. |
| 23 | The **Add a New Practice form** saves to **Netlify Blobs** through an Astro API route (`src/pages/api/practices.ts`, run as a Netlify Function via `@astrojs/netlify`). The lookup fetches `/api/practices/added` on load and merges it with `practices.csv`, which wins on conflicts. | Business leaders expect a practice to appear as soon as they submit it. Blobs needs no database or extra service, and the adapter emulates it locally so `npm run dev` works the same. Every other page stays static. |
| 24 | Hours are entered as open/close times with a "Closed all day" box and converted to the existing `8:00 AM – 5:00 PM` format. Lunch breaks and other exceptions go in Notes. | Free text produced inconsistent formats. Time pickers keep every row in the same format. |
| 25 | Submissions require a **team passcode** (`PRACTICE_FORM_PASSCODE`), checked on the server with a constant-time compare. The server re-validates every field and rejects numbers already in the CSV or in Blobs. | The site is public with no sign-in, so without a passcode anyone with the URL could add practices. The browser checks are only for convenience. |
| 26 | The adapter's Edge Functions dev emulation is turned off (`devFeatures.edgeFunctions: false`). | It needs Deno installed and crashed `npm run dev` without it. The site has no Edge Functions. |
| 27 | **`GET /api/practices`** returns `practices.csv` only, as an array sorted by a new required **`date_added`** column (newest first; same-date rows in reverse file order). Form-added practices moved to `GET /api/practices/added`. Existing rows were given 2026-10-31. | Requested: a CSV-only list, most recent first, in the lookup card's shape. An array keeps the order explicit, where an object keyed by number wouldn't. The CSV had no date to sort by, so one was added and validated like `dateAdded` in documents.yaml. |
| 28 | **`GET /api/summary`** covers a rolling 7 days ending today in `SITE_TIMEZONE`, from `practices.csv` only. "Modified" comes from a new optional **`date_modified`** column (must be a real date, not before `date_added`). A practice added and modified in the same week is listed under `added` only. | The CSV had no record of edits, and the deployed function can't see Git history, so the date is kept in the row. A rolling window means the summary is never empty on a Monday. Listing each practice once keeps the counts honest. |
| 29 | **`POST /api/practices`** appends each submission to **`entries.csv`**, a single CSV file in Netlify Blobs (not a file in the repo), with the `practices.csv` columns plus `submitted_by`, `email`, `submitted_at`. It returns the saved rows. Replaces the earlier one-blob-per-number storage. | Netlify's deployed files are read-only, so a real `data/entries.csv` couldn't be written from the live site. Keeping one CSV in Blobs gives a single downloadable file (`/api/entries.csv`) whose rows paste straight into `practices.csv`. |
| 30 | Appends use a read → conditional write (`onlyIfMatch` etag) → **re-read to confirm** loop, and only report success once a read shows the new rows. The etag is taken from `list()`. | Two submissions at once must not overwrite each other. The local Blobs emulator returns no etag from `get`/`head`, and its etag check isn't atomic: in testing, 5 simultaneous submits all returned 201 but one row was lost. With the confirm step, 3 rounds of 8 simultaneous submits saved all 24 rows. |
| 31 | Phone numbers are checked on the server **as typed**, before formatting is stripped: required, no letters, not negative, only digits/spaces/( ) - . +, then 10 digits (a leading 1 is dropped). The form sends the lines as typed. A 400 that is only about phone numbers includes `field: "numbers"` so the form highlights that box. | Stripping first silently turned `813-555-0101x` or `-8135550101` into valid numbers. In testing, the form itself stripped letters before sending, so it now sends raw values and the server decides. |
| 32 | **`GET /api/export`** downloads `entries.csv` as `entries-YYYY-MM-DD.csv` (date in `SITE_TIMEZONE`) with a UTF-8 byte order mark. `/api/entries.csv` stays as the plain file. | A dated name keeps repeated exports apart. Without the BOM, Excel on Windows shows the – in hours as garbled characters (the same problem section 4 warns about). The CSV parsers here skip the BOM, so exported rows still paste into `practices.csv`. |
| 33 | **Hours of operation are required** on the form: every day needs opening and closing times or "Closed all day". The server also requires all 7 days and checks each is `h:mm AM – h:mm PM` (en dash) or `Closed`. `practices.csv` still allows blank days (shown as "Not listed"). | Requested. Checking the format on the server keeps API submissions consistent with what the form produces and the lookup displays. The CSV rule is unchanged so existing hand-edited rows still build. |
